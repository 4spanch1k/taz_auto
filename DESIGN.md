# TAZ — дизайн-система и UI-гайд

Версия: 1.0

Статус: рабочий источник правил для текущего React/Vite-прототипа
Актуально для: `/market`, `/market/hyundai`, `/about`, `/parts`, `/accessories`

## 1. Зачем существует этот документ

TAZ — сервис, который помогает выбрать автомобиль в Дубае, проверить условия покупки и организовать доставку в Казахстан. Интерфейс должен поддерживать этот сценарий: быстро привести человека к каталогу, объяснить импорт короткими шагами и не перегружать страницу устаревшими маркетплейс-разделами.

Это не копия визуального языка Mycar. Референс помог изучить структуру каталога, но у TAZ своя навигация, своя задача — импорт из Дубая — и свой набор сервисных страниц.

### Главная идея

Чистый светлый интерфейс с крупной типографикой, реальными автомобилями как главным визуальным материалом и одним синим действием. Карточки используются только там, где пользователь выбирает машину или марку; в остальных местах приоритет у пространства, сетки и тонких разделителей.

## 2. Принципы

1. **Каталог — первый путь.** С любого экрана должно быть понятно, как вернуться к маркам автомобилей.
2. **Импорт объясняется последовательно.** Четыре шага показываются вертикально, без анимаций, прыжков и подсветок.
3. **Один акцент на один смысл.** Индиго — стандартное действие и навигация; оранжевый — только CTA импорта, когда он появляется.
4. **Автомобиль важнее декоративного UI.** Фото и логотип марки должны быть чистыми, без лишнего текста, полос или обрезанного переднего ракурса.
5. **Меньше навигации, больше смысла.** В шапке и меню только: каталог, TAZ, запчасти, аксессуары.
6. **Светлая поверхность по умолчанию.** Тёмная тема допустима лишь как локальный остров процесса импорта, а не как глобальный режим.

## 3. Дизайн-токены

`src/tokens.css` — единственный источник цветов, радиусов, пространства и шрифтов. В компонентах и CSS используются прежде всего semantic-токены, а не сырые HEX-значения.

### Цвета

| Роль | Token | Значение | Использование |
| --- | --- | --- | --- |
| Фон страницы | `--bg-page` | `#F1F4F8` | Основной светло-серый фон |
| Поверхность | `--bg-surface` | `#FFFFFF` | Шапка, карточки, модальные окна |
| Чип / выбор города | `--bg-chip` | `#D8E6FB` | Спокойное акцентное состояние |
| Основной текст | `--text-body` | `#1F2937` | Обычный текст |
| Заголовок | `--text-heading` | `#121E2F` | H1 и большие заголовки |
| Заголовок карточки | `--text-heading-card` | `#111820` | Марки, модели, карточки |
| Вторичный текст | `--text-muted` | `#63748A` | Описания, модели, служебный текст |

Примитивы существуют внутри `tokens.css`, но не должны напрямую попадать в компоненты:

--white: #FFFFFF;
--ink-700: #1F2937;
--ink-900: #121E2F;

--slate-500: #63748A;
--blue-600: #0068E3;
--indigo-600: #263AD7;

### Радиусы и тени

| Роль | Token | Значение |
| --- | --- | --- |
| Обычный контрол | `--radius-control` | `8px` |
| Большой контрол | `--radius-control-lg` | `12px` |
| Карточка | `--radius-card` | `16px` |
| Шапка | `--shadow-header` | `0 0 16px rgba(0, 0, 0, .1)` |

Не используем круглые `pill`-кнопки по умолчанию. Исключения: выбор города, количество и действия, в которых форма несёт полезный смысл.

### Шкала отступов

| Token | Значение | Пример |

| Token | Значение | Роль |

## 4. Типографика

Используются только две гарнитуры.

| Роль | Шрифт | Вес | Правило |
| --- | --- | --- | --- |
| Заголовки | `Okto` | 700 | Крупные заголовки, названия марок и моделей |
| Основной текст | `InterDisplay` | 400–700 | Навигация, описания, цены, кнопки |

### Иерархия

| Элемент | Desktop | Mobile | Примечание |
| --- | --- | --- | --- |
| H1 сервисной страницы | `40–72px / 1` | `40px / 42px` | Небольшой трекинг в минус |
| H1 каталога | `36px / 40px` | `20px / 24px` | «Выберите марку» |
| H2 секции | `24–28px` | `20–24px` | Короткая формулировка действия |
| H3 в сервисной сетке | `21px / 26px` | `19px / 24px` | Подзаголовок без лишнего веса |
| Карточка марки | `22px / 28px` | `17px / 20px` | Название марки |
| Описание | `15–20px` | `14–17px` | Вторичный цвет |
| Навигация | `14px` | `17px` в drawer | На mobile увеличена зона нажатия |

## 5. Сетка и адаптивность

### Общие правила

- Контент располагается в `.container` шириной до `1200px`.
- До `1200px` появляются горизонтальные отступы по `16px`.
- Шапка липкая, высотой `56px`.
- Не использовать CSS-переменные внутри `@media`: для Lightning CSS брейкпоинты должны быть литеральными.

### Брейкпоинты

| Ширина | Режим |
| --- | --- |
| `≥ 1201px` | полный desktop-контейнер |
| `1024–1200px` | tablet / compact desktop с gutter `16px` |
| `≤ 1023px` | mobile-header, боковое меню, две колонки марок |
| `≤ 767px` | phone-типографика, один столбец сервисных описаний |

### Каталог

| Экран | Сетка марок | Высота карточки |
| --- | --- | --- |
| Desktop | 5 колонок | `196px` |
| Tablet / Mobile | 2 колонки | `128px` |

### Популярные автомобили

| Экран | Сетка | Высота карточки |
| --- | --- | --- |
| Desktop | 4 колонки | `200px` |
| Tablet | 3 колонки | `145px` |
| Phone | 3 колонки | `115px` |

## 6. Навигация

### Единая карта разделов

| Пункт | URL | Назначение |
| --- | --- | --- |
| Каталог | `/market` | Марки и популярные авто из Дубая |
| Что такое TAZ | `/about` | Как работает услуга импорта |
| Автозапчасти TAZ | `/parts` | Категории комплектующих |
| Авто аксессуары TAZ | `/accessories` | Категории аксессуаров |

### Desktop header

- Логотип ведёт в `/market`.
- Четыре пункта меню совпадают с mobile drawer и являются обычными ссылками.
- У активного пункта — тёмный текст и нижняя линия `2px`.
- Для всех `/market/*`, включая Hyundai, активен «Каталог».
- В desktop-шапке нет старых пунктов Mycar, выпадающего «Все сервисы», переключателя темы и языка.

### Mobile header и drawer

- Шапка: menu, логотип, иконка профиля.
- Drawer: только четыре базовых пункта из таблицы выше.
- Поверх страницы появляется затемняющий слой; меню закрывается по scrim, крестику и переходу по ссылке.
- Ширина drawer: до `340px` или `86vw`.

## 7. Компоненты

### Карточка марки

**Назначение:** выбор марки и переход в каталог марки.

- Белая поверхность, тонкая граница, `--radius-card`.
- Слева сверху: настоящий логотип марки.
- Ниже: название и модель.
- Автомобиль расположен внизу справа, в едином переднем three-quarter ракурсе.
- Для Rolls-Royce, Mercedes-Benz и Porsche применяется отдельный класс `.brand-card--front`, чтобы позиция совпадала с другими карточками.
- На hover допустим только лёгкий сдвиг вверх на `1px` и нейтральный фон. Никакого подпрыгивания постоянно и никакой синей подсветки.

### Карточка популярного автомобиля

**Назначение:** показать востребованные модели из Дубая без кредитного расчёта.

- Изображение полностью заполняет карточку через `object-fit: cover`.
- Поверх нижней части — чёрный градиент только ради читаемости текста.
- В карточке только: марка + модель и цена `от … ₸`.
- Дополнительные строки вроде «в кредит от …» не используются.
- Изображения Mercedes S-Class, Porsche 911 и Jetour T2 должны показывать переднюю часть автомобиля и не содержать чёрных полос. Для Jetour применён увеличенный crop.

### Шаги импорта

**Назначение:** кратко объяснить путь автомобиля.

1. Выбор
2. Проверка
3. Импорт
4. Получение

- Вертикальная последовательность белых блоков с синим номером и меткой.
- Синяя подсветка, интерактивное мерцание и «подпрыгивание» запрещены.
- На desktop и mobile сохраняется именно вертикальная логика, а не горизонтальная карусель.

### Выбор города

- Мягкий голубой chip с текстовой ссылкой.
- Модальное окно на белой поверхности с поиском, крупными городами и списком остальных.
- В фокусе должен быть видимый контур; поиск получает фокус при открытии.

### Лендинг «Что такое TAZ»

`/about` — полноценный landing об импорте автомобилей из Дубая.

1. Тёмный hero с локальным изображением автомобиля, eyebrow, H1 и двумя CTA.
2. Четыре направления сопровождения.
3. Вертикальный процесс импорта из четырёх шагов.
4. Категории автомобилей с локальными фотографиями.
5. Блок проверок до выкупа и блок прозрачности процесса.
6. Нативный FAQ на `<details>` / `<summary>`.
7. Финальный CTA в каталог.

На mobile hero сохраняет читаемый тёмный слой, CTA становятся вертикальными, а все сетки переходят в один столбец.

### Страницы запчастей и аксессуаров

`/parts` и `/accessories` используют более короткий шаблон:

1. Eyebrow с названием сервиса.
2. Большой H1.
3. Одно короткое описание.
4. Кнопка «Открыть каталог».
5. Двухколоночная сетка смысловых пунктов с тонкими разделителями.

На mobile сетка превращается в один столбец, а кнопка занимает всю ширину.

### Footer

Footer предельно короткий:

- логотип TAZ;
- копирайт;
- телефон;
- email.

Не добавлять назад SEO-списки брендов, городов, юридические ссылки или старую структуру Mycar без отдельной продуктовой задачи.

## 8. Изображения и брендинг

- Использовать реальные локальные assets из `public/assets`.
- Логотип бренда — отдельный asset, не текстовая имитация.
- У изображений есть осмысленный `alt`: «Марка Модель».
- Не использовать в карточках автомобильные фото со вшитыми текстами, UI-элементами или случайными чёрными полосами.
- Не смешивать разные ракурсы машин в одной сетке: приоритет — фронтальный/передний three-quarter.
- Текст на фото допустим в overlay популярного автомобиля и в hero `/about`; в обоих случаях нужен тёмный слой для контраста.

## 9. Состояния и взаимодействия

| Элемент | Default | Hover / Focus | Ограничение |
| --- | --- | --- | --- |
| Ссылка навигации | muted text | heading text, active underline | Нет декоративной анимации |
| Primary CTA | indigo | лёгкое затемнение | Высокий контраст текста |
| Карточка марки | white surface | нейтральный фон, `translateY(-1px)` | Без постоянного движения |
| Карточка авто | изображение | умеренный zoom изображения | Без увеличения текста |
| Drawer | скрыт | затемнение scrim | Закрывается несколькими способами |
| Город | blue chip | чуть более насыщенный chip | Не делать primary CTA |

## 10. Доступность

- Интерактивные элементы используют нативные `<a>` и `<button>`.
- Все icon-only кнопки получают `aria-label`.
- Название марки и модели передаётся в `alt` изображения автомобиля.
- Ссылки должны иметь видимое focus-состояние, а не только hover.
- Контраст вторичного текста проверять до добавления новых оттенков; для обычного текста нужен минимум WCAG AA.
- Не добавлять информацию, которая считывается только по цвету или только по hover.

## 11. Интеграция с shadcn

В проекте пока нет Tailwind runtime. `tailwind.config.js` готовит semantic-маппинг для будущего подключения, но текущий интерфейс стилизуется через `src/styles.css` и CSS-переменные.

При добавлении shadcn-компонента:

1. Сначала использовать semantic token из `tokens.css`.
2. Сохранять радиусы `control`, `control-lg`, `card`.
3. Не использовать `accent` для обычных кнопок — только для импорта.
4. Не включать глобальный dark mode. Класс `.dark-island` допустим исключительно внутри import workflow.
5. Не копировать компоненты shadcn без адаптации к двум шрифтам и TAZ spacing.

## 12. Правила для новых экранов

### Делать

- Начинать с одного ясного H1 и одного primary-действия.
- Использовать страницу и поверхность из токенов.
- Ставить делители и сетку вместо множества карточек.
- Показывать реальные данные или явно маркировать будущую функцию.
- Проверять desktop и mobile после каждой визуальной правки.

### Не делать

- Не возвращать SEO-хвосты внизу каталога.
- Не добавлять авто-кредит, дилерские центры или города, если экран про импорт из Дубая.
- Не добавлять более одного яркого CTA на секцию.
- Не использовать тёмные градиенты как декоративный фон обычных разделов.
- Не повторять визуальный язык Mycar: старую навигацию, лишние footer-группы, калькулятор и dealer-списки.

## 14. Где менять систему

| Что меняется | Файл |
| --- | --- |
| Semantic-токены, шрифты, spacing | `src/tokens.css` |
| Компоненты, маршруты, контент | `src/main.jsx` |
| Layout, responsive-правила, визуальные состояния | `src/styles.css` |
| Подготовка Tailwind/shadcn mapping | `tailwind.config.js` |

Перед изменением значений сначала обновить этот документ и `tokens.css`, затем заменить совпадающие значения в компонентах. Не вводить новый цвет, радиус или постоянный отступ без роли в системе.
